赤を入れられるようになる14単元

Claude Academy の Introduction to Claude Cowork が扱う業務ユースケース—— スプレッドシートの片付け、文書の統合、文章の量産、繰り返し作業の自動化——を、 Claude Code でそのまま実践できる形に置き換えた教材です。

Cowork がデスクトップのファイルとアプリを相手にするのに対して、Claude Code が相手にするのは リポジトリとターミナル。やることは同じでも、出力先がパスで決まり、 git diff で何をされたか全部見え、 検収を人ではなくスクリプトに書ける。この違いが、実務で任せられる範囲を決めます。

教材データは意図的に壊してあります。表記ゆれ、和暦、全角数字、重複行、 領収書とカード明細の二重計上、未回答のセキュリティ質問票。 きれいなサンプルからは、赤の入れ方は学べないからです。

最後の2単元は、リポジトリの外——ブラウザに出ます。ログイン付きの業務システムを 1本同梱してあり、わざと自動化しにくく作ってあります。 スケルトン行、デバウンス、ページ送り、非同期ジョブ、セッション失効。 現場で RPA が転ぶ場所を16個そろえました。

教材データについて

架空のSaaS企業「株式会社アルタイル」（製品 Altair CRM、社員240名）が舞台。 14単元すべてが同じ会社・同じ顧客・同じ数字でつながっています。

単元04 の売上Excelに仕込んである壊れ方

    再生成できる

    データ生成スクリプトは乱数シードを固定してあります。演習で data/ を壊しても、同じデータがそのまま戻ります。 

    # 初回、または data/ を壊したとき
pip install openpyxl python-docx python-pptx
python3 tools/generate_all.py

# → units/ 配下に 146 ファイル

    単元04・08・12・14 には検証スクリプトを書かせる課題が含まれます。 30通の Word 文書を目視で確認するのは現実的ではないので、 検収そのものをコードにするのが答えです。

    単元13・14 には、練習台のシステムが付いています

    apps/rpa-lab/ — 架空企業の受注管理システム。ログイン、4ステップのウィザード、承認フロー、 非同期のレポート生成。わざと自動化しにくく作ってあります。 依存パッケージはゼロで、Vercel にもそのまま乗ります。

    仕込んである16個の「困りごと」から

      起動して、Claude Code をつなぐ

      # 練習台を立てる（Node 20 以上、npm install 不要）
cd apps/rpa-lab && npm run dev
# → http://localhost:4321

# ルートA: Chrome 拡張（対話向き・既存ログインを共有）
claude --chrome

# ルートB: Playwright（無人実行・定期実行向き）
claude mcp add playwright -- npx -y @playwright/mcp@latest

      Chrome 拡張はあなたのブラウザのログイン状態を共有します。 つまり「自動ログイン」の正体は、ログインしないこと。そして拡張は ログイン画面や CAPTCHA に出会うと手を止めて人に渡します——それが設計です。 無人で回すなら Playwright に切り替え、セッションを保存して再利用します。

      全単元に通底する4つのルール

      Cowork でも Claude Code でも変わらない、AIに仕事を任せるときの基本です。

      ただし単元13・14 のブラウザだけは、RULE 02 が使えません。押したら戻せないからです。 退避の代わりに、件数を先に宣言する・2回動いても二重にならないようにする・ 実行ログを残す。この3つで代替します。

      はじめかた

      各単元の README に、そのままコピーして使えるプロンプトが載っています。最初は写経で構いません。

      1. リポジトリを開いて、教材データを作る

        教材の実データはリポジトリに入っていますが、壊したときはここで戻せます。

        git clone <このリポジトリ>
cd claude-code-pra
pip install openpyxl python-docx python-pptx
python3 tools/generate_all.py

      2. 権限モードを「確認あり」にして起動する

        Shift+Tab でモードを切り替えられます。最初は必ず確認ありで、何をされているかを見てください。

        claude

      3. 単元01 の README を開く

        3人分の日報と数値CSVから週報を1枚作ります。ここで「依頼 → 計画の確認 → 実行 → 自分で検収」を1周します。

        # Claude Code に投げる
週報を作ってください。
@units/01-setup-first-loop/data/ を読んで、
書式は data/週報の書式.md に従う。
出力は units/01-setup-first-loop/output/週報_2026-W36.md

      4. 単元09 まで来たら、CLAUDE.md を書く

        毎回プロンプトに書いていた制約を常設のコンテキストに移します。ここから先、依頼が一気に短くなります。

      教材内の会社名・人名・数値はすべて架空のものです。Claude Academy の公式教材ではなく、 そのユースケースを Claude Code 向けに再構成した非公式教材です。

      単元の実体は units/<単元>/ にあります。 README.md（指示書）／data/（入力・読み取り専用）／output/（成果物）／solution/（模範解答・一部）。 単元13・14 の練習台は apps/rpa-lab/。ログイン情報はダミーで、本番で使えるものは含まれていません。
