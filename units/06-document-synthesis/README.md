# 単元06 複数文書の統合 — ベンダー3社の提案を1枚にまとめる

|  |  |
|---|---|
| Cowork のユースケース | 複数のドキュメントを読ませて、意思決定できる形に統合する |
| Claude Code での対応 | RFP・提案書3社（docx/md）・コスト表・情シスメモから、経営会議用の判断資料を作る |
| 所要時間 | 50分 |
| 使う機能 | `docx` / `pptx` / `xlsx` スキル / 複数形式の横断読み取り |

## この単元でやること

RFPとベンダー3社の提案（docx 2本・md 1本）、コスト表、情シスの下書きメモを横断して、
経営会議が20分で判断できる資料にまとめます。難しいのは要約ではなく、**土俵を揃えること**です。
3社の見積は前提が揃っておらず、そのまま合計金額を並べると比較になりません。
さらに、3社のどの提案書にも書かれていない論点（移行スコープ）が情シスメモにだけ埋まっています。

| | |
|---|---|
| 入力 | RFP ＋ 提案3社（docx/md）＋ 現行コストとセキュリティ比較.xlsx ＋ 情シス所見メモ.txt |
| 出力 | `output/比較表.xlsx`（5シート）＋ `output/意思決定サマリ.md`（50行以内）＋ `output/経営会議_ベンダー選定.pptx`（6枚） |
| 中心にある判断 | 提案書の自己申告をそのまま並べないこと。書かれていなければ「記載なし」と書かせる |

## 成功の定義

> **見積の前提が揃っていない点が比較表より前に書かれ、提案書に載っていない論点が「決めていただきたいこと」に上がっていること。**

次が満たせていれば合格です。細かい確認項目は末尾の「合格チェック」にあります。

- A社の見積前提（米国リージョン / 国内保管には年420万円追加）が指摘されている
- C社の稼働時期（2027年3月）が M-06 に、監査ログ13ヶ月が M-02 に不適合と書かれている
- B社の Factory Nexus コネクタ 320万円が費用表に載っている
- 移行スコープ（120万 vs 実質40万レコード）が「決めていただきたいこと」に入っている
- 情シスメモ由来の伝聞に「未確認」の注記が付いている

## 学習目標

1. 形式の違う文書（docx / md / xlsx / txt）を横断して、**同じ軸で比較**する。
2. 「書いてあること」と「書かれていないこと」を分けて扱う。
3. 提案書の **前提条件の違い**（見積の土俵が揃っていない）を見つける。

## 素材

```
data/
  RFP_要件定義.md                     必須6件(M-01〜06) / 推奨4件(W-01〜04) / 予算 / 評価配点
  提案_A社_Northwind.docx             機能は最厚。ただし見積の前提が米国リージョン
  提案_B社_Meridian.docx              要件適合は良い。移行はパートナー任せ
  提案_C社_Kestrel.md                 安いが監査ログ13ヶ月、稼働が2027年3月
  現行コストとセキュリティ比較.xlsx    現行運用コスト / セキュリティ質問票10問の3社回答
  情シス所見メモ.txt                  共有前の下書き。伝聞と未確認情報が混ざっている
```

### 資料に埋め込まれた「気づいてほしい点」

1. **A社の見積は国内保管が前提になっていない。** Enterprise Plus への変更で年420万円増える。
   5年TCOが 1億6,100万円 → 実質さらに上振れし、予算上限（1億2,000万円）を大きく超える。
2. **C社の本番稼働 2027年3月は、現行サポート終了と同月。** M-06（2027年1月末）に適合しない。
   さらに監査ログは標準13ヶ月で M-02 に適合せず、オプション年180万円が必要。
3. **B社の Factory Nexus コネクタは新規開発で別途320万円。** 見積合計に含まれていない。
4. **C社はセキュリティ質問票の2問が未回答**（ペネトレ頻度・インシデント通知SLA）。
5. **情シスメモの「移行対象は実質40万レコード」は、3社の提案書のどこにも書かれていない。**
   これはベンダー比較の前に、**社内でスコープを決め直すべき論点**。
6. 情シスメモには **伝聞（未確認）** が含まれる。資料に載せるなら出典を明示する必要がある。

## 手順

### Step 1 — 比較軸を先に固定する（10分）

いきなり「まとめて」と言わない。RFPの評価配点（機能適合30/コスト25/移行リスク20/
セキュリティ15/サポート10）を比較軸として先に宣言する。

### Step 2 — 事実の抽出と矛盾検出（20分）

### Step 3 — 判断資料を作る（15分）

### Step 4 — 「書かれていないこと」を確認する（5分）

出てきた資料に、上の「気づいてほしい点」6つが載っているか確認する。

## つまずきポイント

- **「3社を比較して」だけだと、提案書の自己申告をそのまま並べる**
  → 「書かれていなければ記載なし」と明示する。○△×の△の中身が一番重要。
- **合計金額をそのまま信じる**
  → オプション・前提条件を別行にする指示を入れる。土俵を揃えるのが比較の本体。
- **情シスメモの噂を根拠に使ってしまう**
  → 出典の信頼度で扱いを変えるルールをプロンプトに書く。
- **pptx が文字だらけになる**
  → 「1枚7行以内」のような機械的な制約を置く。

## 発展課題

推奨した社について、契約前に確認すべき質問リスト（10問）を
`output/ベンダー確認事項.md` として作る。「比較表のシート5に載った項目」から機械的に導ける。
