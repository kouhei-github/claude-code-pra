# 単元04 スプレッドシートのクリーンアップ

|  |  |
|---|---|
| Cowork のユースケース | 汚れた表計算ファイルを整えて、集計できる状態にする |
| Claude Code での対応 | 表記ゆれ・型崩れ・重複を含む売上Excelを正規化し、判断できない行を退避する |
| 所要時間 | 45分 |
| 使う機能 | `xlsx` スキル / Python（openpyxl）/ 検証スクリプト |

## この単元でやること

13種類の壊れ方を仕込んだ124行の売上Excelを、集計できる状態にします。
順番が決まっています。**診断（何が壊れているかの一覧）→ 変換ルールを人が決める → クリーニング → 検証**。
とくに「金額が数量×単価と合わない行」をどう扱うかは Claude に決めさせません。
値引きかもしれないからです。直せない行は捨てずに、理由付きで除外シートへ退避させます。

| | |
|---|---|
| 入力 | 売上データ_2026上期_raw.xlsx（売上明細・商品マスタ・メモの3シート） |
| 出力 | `output/売上データ_2026上期_clean.xlsx`（4シート）＋ `output/診断レポート.md` ＋ `output/verify.py` |
| 中心にある判断 | 曖昧な行の扱いを人が決めること。補完するのか、除外するのか、その理由を残すのか |

## 成功の定義

> **自分で書いた検証スクリプトが全項目 PASS し、判断できなかった行が1件残らず除外シートに理由付きで載っていること。**

次が満たせていれば合格です。細かい確認項目は末尾の「合格チェック」にあります。

- 検証スクリプトが全項目 PASS（行数の保存・日付型・商品コードの整合など）
- 除外行シートに重複6行・小計2行・金額不一致の行がすべて理由付きで載っている
- 「変換ルール」シートを読めば第三者が同じ変換を再現できる
- 入力ファイルのハッシュが作業前後で変わっていない

## 学習目標

1. 「きれいにして」ではなく、**崩れ方を先に列挙させてから**直させる。
2. 直せない行を **勝手に捨てさせない**（除外シートに理由付きで退避）。
3. 変換ルールを表に残し、あとから第三者が検証できる状態にする。

## 手順

### Step 1 — 診断させる（15分）

いきなり直させない。まず **何が壊れているかの一覧**を出させる。
これは「Claude が問題を正しく認識できているか」を確認する工程であり、
同時に人間側が「直し方の方針」を決める材料になる。

### Step 2 — 変換ルールを決める（10分）

診断結果を見て、**曖昧な判断**をどうするか人間が決める。例：

| 崩れ | 直し方の判断 |
|---|---|
| 金額が空欄 | 数量 × 単価で補完する？ それとも除外？ → **補完し、`補完` フラグを立てる** |
| 金額が計算と不一致 | 値引きの可能性がある → **元の値を残し、`要確認` として除外シートへ** |
| 完全重複 | 1件だけ残す。ただし除外シートに記録 |
| 小計行 | 除外。ただし合計値の検算に使う |

**この判断を人間がやることが、この単元の中心。** Claude に決めさせない。

【出力】units/04-spreadsheet-cleanup/output/診断レポート.md

@units/04-spreadsheet-cleanup/output/診断レポート.md をもとに、
売上明細をクリーニングしてください。

【出力】units/04-spreadsheet-cleanup/output/売上データ_2026上期_clean.xlsx
  シート1「売上明細_clean」: 日付(日付型) | 支店 | 担当者 | 商品コード | 商品名 |
      数量(整数) | 単価(整数) | 金額(整数) | 販路 | 備考 | 補完フラグ
  シート2「除外行」: 元の行番号 | 元データそのまま | 除外理由
  シート3「変換ルール」: 列 | 変換前 | 変換後 | 適用件数
  シート4「検算」: クリーン後の合計金額 | 元データの合計（小計行を除く）| 差額

【変換ルール】
- 支店・担当者・商品名: 半角カナ→全角、前後空白除去、全角空白→無し、マスタ表記に統一
- 商品コード: 大文字 + ハイフンあり（P-001形式）に統一。全角英字は半角化
- 日付: すべて日付型。令和表記・ドット区切りも変換する
- 数量/単価/金額: 整数。全角数字・カンマ・「個」「¥」を除去
- 金額が空欄: 数量 × 単価 で補完し、補完フラグ列に「補完」と記入

- 完全重複: 最初の1件を残し、残りは「除外行」へ。理由「重複」
- 小計行・空行・注記行: 「除外行」へ。理由「表外の行」

【制約】
- 入力ファイルは変更しない
- 判断に迷った行を勝手に捨てない。必ず「除外行」に理由付きで残す
- 除外行の件数と、元データの行数の合計が一致することを確認する

## つまずきポイント

- **「きれいにして」だけ投げると、判断に迷った行を黙って消す**
  → 除外シートを必ず作らせる。これが一番大事なルール。
- **金額不一致を機械的に上書きしてしまう**
  → 値引きかもしれない。データが語らないことは人間に返す。
- **令和表記を読み飛ばす**
  → 診断フェーズで「日付の表記パターンを列挙」させておけば漏れにくい。
- **ヘッダーを1行目だと決め打つ**
  → 「ヘッダーが何行目か、その根拠」を先に答えさせる。
