# 単元02 プロンプト設計 — Task / Context / Format / Constraints

|  |  |
|---|---|
| Cowork のユースケース | 構造化プロンプト（task・context・format・constraints）で依頼する |
| Claude Code での対応 | 雑な依頼10件を4要素に分解して書き直し、実際に走らせて採点する |
| 所要時間 | 40分 |
| 使う機能 | Plan mode / `/clear` による再現性テスト |

## 学習目標

1. 4要素（Task / Context / Format / Constraints）で依頼を組み立てられる。
2. 「Format が甘いと検収できない」ことを、失敗を通じて理解する。
3. 同じプロンプトを2回投げて同じ成果物が出るか、という **再現性** で品質を測る。

## 素材

```
data/
  雑なプロンプト集.md          現場で実際に投げられた10件 + 会社の前提情報
  評価基準.md                  4要素の採点ルーブリック（0-3点）
  プロンプト評価シート.xlsx     採点を記録する（合計・合否は数式が入っている）
```

## この単元の考え方

Cowork の講座では「task・context・format・constraints」を教える。Claude Code でも同じだが、
**Format の重みが桁違いに大きい**。Cowork は画面に結果が出るが、Claude Code は
「どのパスに、どの形式で、何を書くか」が決まっていないと、そもそも成果物が確定しない。

| 要素 | Claude Code での具体例 |
|---|---|
| Task | 「売上データを月次・支店別に集計する」 |
| Context | 「読み手は営業本部長。入力は `data/売上データ_2026上期_raw.xlsx` の『売上明細』シート」 |
| Format | 「`output/月次集計.xlsx` に出力。シートは『月次集計』『支店別』『除外行』の3枚」 |
| Constraints | 「入力ファイルは変更しない。判定できない行は削除せず『除外行』シートへ理由付きで退避する」 |

## 手順

### Step 1 — 素材を読む（5分）

`data/雑なプロンプト集.md` の末尾にある「この会社の前提」を必ず読む。
Context を書くための材料はここにある。

### Step 2 — 3件を書き直す（15分）

まずは No.1・No.6・No.10 の3件を、自分の手で書き直す。**Claude に書かせない。**
書き直したら `プロンプト評価シート.xlsx` の C列に貼り、D〜G列を自分で採点する。

### Step 3 — 実際に走らせる（10分）

書き直したプロンプトを Claude Code に投げる。J列に「実行して分かったこと」を書く。
だいたい、ここで **Format の穴**が見つかる（出力先が決まっていない、章立てが曖昧、など）。

### Step 4 — Claude に添削させる（10分）

残り7件は Claude に手伝わせる。ただし丸投げではなく、**採点者として使う**。

## そのまま使えるプロンプト

**（A）添削してもらう**

```
@units/02-prompt-design/data/評価基準.md の4要素ルーブリックで、
以下のプロンプトを採点してください。

---
（ここに自分が書き直したプロンプトを貼る）
---

【出力形式】
1. 要素ごとの点数（0-3）と、その点数にした理由を1文ずつ
2. 合計点と合否（合格ラインは合計10点以上かつFormat 2点以上）
3. 「あと1点上げるために足すべき一文」を、要素ごとに具体的な日本語で

【制約】
- 点数を甘くつけない。曖昧な表現が1つでもあれば2点以下にする
- 書き直し版を全部書いてしまわない。足すべき一文だけを示す
```

**（B）残り7件をまとめて処理する**

```
@units/02-prompt-design/data/雑なプロンプト集.md の No.2〜5, 7〜9 について、
末尾の「この会社の前提」を踏まえて、4要素に分解した書き直し版を作ってください。

【出力】units/02-prompt-design/output/書き直し版.md
  各件について「元のプロンプト / Task / Context / Format / Constraints / 統合版」の順に記載

【制約】
- Format には必ず「出力ファイルのパス」「形式」「章立てまたは列構成」「分量」を含める
- Constraints には必ず「やってはいけないこと」と「判断に迷ったときどうするか」を含める
- 前提に書かれていない事実（社名・数字・日付）を創作しない
```

## 成果物

- `output/書き直し版.md`
- 記入済みの `プロンプト評価シート.xlsx`（`output/` にコピーして記入する）

## 合格チェック

- [ ] 10件すべてが合計10点以上、かつ Format が2点以上
- [ ] Format にファイルパスが書かれている（10件すべて）
- [ ] Constraints に「不明時の振る舞い」が書かれている（10件すべて）
- [ ] 少なくとも1件は実際に走らせて、成果物を確認した
- [ ] `/clear` して同じプロンプトを再実行し、同じ構造の成果物が出た

## つまずきポイント

- **「わかりやすく」「いい感じに」が残っている**
  → 判定できない言葉は0〜1点。「A4 1枚」「3行以内」「表の列は◯◯」に置き換える。
- **Constraints が精神論になる**
  → 「丁寧に」ではなく「data/ 配下を変更しない」「推測で埋めない」。禁止と手順で書く。
- **書き直したら長くなりすぎた**
  → 長さは問題ではない。ただし同じことを2回言っていないかは確認する。

## 発展課題

合格した書き直し版のうち、繰り返し使うものを `.claude/commands/` にスラッシュコマンドとして
保存する。単元10の Skill 化への助走になる。

```bash
mkdir -p .claude/commands
cat > .claude/commands/weekly-report.md <<'CMD'
週報を作ってください。（ここに書き直し版を貼る。$ARGUMENTS で引数を受け取れる）
CMD
```

`/weekly-report` で呼び出せるようになる。
