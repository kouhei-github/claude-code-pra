# 単元01 セットアップと「最初のタスクループ」

|  |  |
|---|---|
| Cowork のユースケース | 作業フォルダを決め、権限モードを選び、最初の依頼をやり切る |
| Claude Code での対応 | リポジトリで `claude` を起動し、権限モードを理解し、計画→実行→検収を1周する |
| 所要時間 | 25分 |
| 使う機能 | 権限モード / Plan mode / `@` によるファイル参照 / `/clear` |

## この単元でやること

営業3人分の日報（テキスト）と今週の数値CSVを渡し、営業本部長に出す週報を1枚作らせます。
いきなり書かせず、まず Plan mode で**計画だけ**立てさせて内容を確かめ、そのうえで実行させます。
出てきた成果物は自分で書式と突き合わせて検収し、最後に `/clear` して同じプロンプトを投げ直します。
2回目も同じものが出れば、そのプロンプトは他人に渡せる品質です。

| | |
|---|---|
| 入力 | 日報3本（txt）＋ 今週の数字.csv ＋ 週報の書式.md |
| 出力 | `output/週報_2026-W36.md`（5章・60行以内） |
| 中心にある判断 | 数字のソースを1つに固定すること。日報の中の数字を根拠にさせない |

## 成功の定義

> **書式どおりの週報が出て、`data/` が1バイトも変わっておらず、`/clear` 後の再実行で同じ構造が出ること。**

次が満たせていれば合格です。細かい確認項目は末尾の「合格チェック」にあります。

- 5つの章が書式どおりの順序で並んでいる
- 数字が `今週の数字.csv` と一致している（新規受注額 13,200,000円 など）
- `git status` が `data/` の変更を1件も出さない
- `/clear` して同じプロンプトを投げると、同じ構造の週報が出る

## 学習目標

1. Cowork の「作業フォルダ」が Claude Code では **カレントディレクトリ** であることを理解する。
2. 3つの権限モードの違いを説明でき、作業内容に応じて選べる。
3. 「依頼 → 計画の確認 → 実行 → 自分で検収」という1周（タスクループ）を体験する。

## Cowork との対応表

| Cowork | Claude Code |
|---|---|
| 作業フォルダを選ぶ | `cd <ディレクトリ>` して `claude` を起動する |
| 権限モード（確認あり/自動） | 起動時のモード、`Shift+Tab` での切り替え、`/permissions` |
| ファイルをドラッグして渡す | `@units/01-setup-first-loop/data/日報_田中_0901-0905.txt` |
| 会話をリセット | `/clear` |
| 作業の途中経過を見る | ターミナルのツール実行ログ、`git diff` |

## 素材

```
data/
  日報_田中_0901-0905.txt      営業（西日本チーム）の1週間の日報
  日報_伊藤_0901-0905.txt      カスタマーサクセスの1週間の日報
  日報_佐藤_0901-0905.txt      パートナー営業の1週間の日報
  今週の数字.csv               今週/前週/目標の5指標
  週報の書式.md                提出フォーマットの決まりごと
```

## 手順

### Step 1 — 起動して現在地を確認する（3分）

```bash
cd /path/to/このリポジトリ
claude
```

最初に、権限モードを確認する。`Shift+Tab` を押すと下部の表示が切り替わる。

| モード | 挙動 | 使いどころ |
|---|---|---|
| 通常（確認あり） | ファイル編集・コマンド実行のたびに承認を求める | **最初はこれ**。何をされるか見える |
| Accept Edits | ファイル編集は自動、コマンドは確認 | 手順が読めている作業 |
| Plan mode | 読み取りのみ。編集・実行をしない | いきなり作業させたくないとき |

まず **Plan mode** に切り替えて、次を投げる。

```
@units/01-setup-first-loop/data/ の中身をすべて読んで、
週報を作るとしたらどういう手順になるか、計画だけ立てて。まだ何も書かないで。
```

計画が返ってきたら、**素材を読み違えていないか**を確認する。ここが検収の1回目。

### Step 2 — 書式を守らせて実行する（10分）

Plan mode を抜けて（`Shift+Tab`）、下の「そのまま使えるプロンプト」を投げる。

### Step 3 — 検収する（7分）

出てきた `output/週報_2026-W36.md` を、**書式.md と突き合わせて**チェックする。
違っていたら、直させる。ここで「なんとなくOK」にしないことが、この単元で一番大事。

### Step 4 — 会話を切る（5分）

```
/clear
```

を実行し、**同じプロンプトをもう一度**投げる。ほぼ同じ成果物が出れば、
そのプロンプトは「他人に渡せる」品質になっている。出なければ、単元02で直す。

- `output/週報_2026-W36.md`

## 合格チェック

- [ ] 5つの章がすべてあり、順序が書式どおり
- [ ] 数字が `今週の数字.csv` と一致している（受注額 13,200,000円 など）
- [ ] 案件が金額の大きい順に並んでいて、5件以内
- [ ] 相談事項に「誰の判断が必要か」が書かれている
- [ ] `data/` のファイルが1つも変更されていない（`git status` で確認）
- [ ] 60行以内

## つまずきポイント

- **勝手に数字を丸める / 日報の記憶で数字を書く**
  → プロンプトで数字のソースを1つに限定する。単元02で扱う「制約」の話。
- **`data/` を書き換えてしまう**
  → 権限モードを通常にしていれば承認画面で止まる。承認画面を読む習慣をつける。
- **60行を大きく超える**
  → 分量指定は「行数」など機械的に判定できる単位で出す。

## 発展課題

`git status` と `git diff` で、Claude が触ったファイルを確認する。
Cowork には無い、Claude Code ならではの安全網がこれ。
以降の単元では、作業の前に必ず `git status` がきれいであることを確認してから始めるとよい。
