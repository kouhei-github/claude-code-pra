# 単元10 業務を Skill にする（月次レポート生成）

|  |  |
|---|---|
| Cowork のユースケース | Skill を作って、自分の手順・語彙・期待する成果物を Claude に覚えさせる |
| Claude Code での対応 | 過去3回の完成品から手順を逆算し、`.claude/skills/` に Skill を作る |
| 所要時間 | 50分 |
| 使う機能 | `.claude/skills/<name>/SKILL.md` / frontmatter の `description` / `/skill-name` |

## 学習目標

1. **過去の成果物から手順を逆算する**（ゼロから手順書を書かない）。
2. Skill の `description` が「いつ発火するか」を決めることを理解する。
3. Skill が独り歩きしないよう、**判断を人に返すポイント**を Skill 内に書く。

## Cowork との対応

| Cowork | Claude Code |
|---|---|
| Skill を作る | `.claude/skills/<name>/SKILL.md` を書く |
| Skill を呼ぶ | `/<name>` または、`description` に合う依頼をすると自動で読み込まれる |
| Skill に添付ファイルを持たせる | Skill ディレクトリに `reference.md` / テンプレート / スクリプトを同梱する |
| プラグインを入れる | `/plugin` でマーケットプレイスから追加、`.claude/settings.json` で管理 |

## 素材

```
data/
  過去の月次レポート/
    月次レポート_2026-06.md    完成品①
    月次レポート_2026-07.md    完成品②
    月次レポート_2026-08.md    完成品③
  今月の素材_2026-09/
    kpi_2026-09.csv                    9月と8月の9指標
    営業ハイライト.md
    サポート状況.md
    解約とエグジットインタビュー.md
```

過去3本のレポートには、明文化されていないが一貫している決まりがある。
それを Claude に **発見させる** のがこの単元の核心。

<details>
<summary>ヒント（Step 1 のあとで開く）</summary>

- 章立ては常に「サマリ / 数字 / ハイライト / リスクと課題 / 来月のアクション」の5章
- サマリは必ず3行。MRRの前月比を `+X.X%` 形式で書く
- 数字の表は6行固定（MRR / 新規 / 解約 / 期末顧客数 / ARPU / 初回応答時間）
- ハイライトは箇条書き2〜3件。数字を必ず1つ含む
- リスクは番号付き2〜3件。「前月から続いているもの」を先に書く
- アクションは表形式で「やること / 担当 / 期限」。担当は姓のみ、期限は M/D 形式
- 末尾に必ず「※ 数字はすべて当社調べ。実績値であり見込値は含まない。」
- 前月のレポートで挙げたリスクが、翌月のレポートに何らかの形で引き継がれている

</details>

## 手順

### Step 1 — 完成品から仕様を逆算させる（15分）

### Step 2 — SKILL.md を書かせる（15分）

### Step 3 — Skill を使って9月分を作る（15分）

### Step 4 — Skill を直す（5分）

出てきた9月レポートを過去3本と並べて、ずれている点を SKILL.md に追記する。

## そのまま使えるプロンプト

**（A）仕様の逆算**

```
@units/10-custom-skill/data/過去の月次レポート/ の3本を読み比べて、
このレポートの「暗黙の仕様」を抽出してください。まだ Skill は作りません。

【出力】units/10-custom-skill/output/仕様の逆算.md
  1. 章構成（順序・章タイトル・各章の分量）
  2. 各章の書き方の決まり（3本すべてに共通しているもの）
  3. 数値表現のルール（単位・桁区切り・増減の書き方・日付形式）
  4. 3本のうち2本にしかない要素（＝ルールか例外か判断がつかないもの）
  5. 前月レポートとの連続性（引き継がれている要素）

【制約】
- 「〜のようだ」で終わらせず、各ルールについて3本での出現を確認して書く
- 3本すべてで一致しているものと、2本のみのものを必ず分ける
```

**（B）SKILL.md の作成**

```
@units/10-custom-skill/output/仕様の逆算.md をもとに、
月次レポートを作る Skill を作ってください。

【出力】units/10-custom-skill/output/skills/monthly-report/SKILL.md

【frontmatter】
---
name: monthly-report
description: <いつ発火すべきかを1〜2文で。「月次レポート」「経営会議の資料」「MRRの月次まとめ」
             といった依頼で発火し、それ以外では発火しないように書く>
---

【本文の構成】
## 入力
  必要な入力ファイルと、揃っていないときにどうするか
## 手順
  番号付き。各ステップは「何をする」「何を確認する」の2文以内
## 出力仕様
  章構成・分量・数値表現のルール（仕様の逆算.md の1〜3をここに落とす）
## 人に確認すること
  Skill が勝手に決めてはいけない判断を列挙する
## 完成チェック
  提出前に自分で確認する項目のチェックリスト

【制約】
- 全体で100行以内
- 「仕様の逆算.md」の4（判断がつかないもの）は、
  勝手にルール化せず「人に確認すること」に入れる
- description に「レポート」「資料」だけの汎用語を使わない（誤発火するため）
```

**（C）Skill を使う**

```
（output/skills/monthly-report/ を .claude/skills/ にコピーしてから）

2026年9月の月次レポートを作ってください。
素材は @units/10-custom-skill/data/今月の素材_2026-09/ です。
出力は units/10-custom-skill/output/月次レポート_2026-09.md。
```

Skill が効いていれば、章立て・分量・文体の指定を **プロンプトに書かなくても**
過去3本と同じ形のレポートが出てくる。

## 成果物

- `output/仕様の逆算.md`
- `output/skills/monthly-report/SKILL.md`（100行以内）
- `output/月次レポート_2026-09.md`

## 合格チェック

- [ ] 9月レポートの章構成が過去3本と完全に一致している
- [ ] サマリが3行で、MRR前月比が `+3.8%` 形式で書かれている
- [ ] 数字の表が6行あり、値が `kpi_2026-09.csv` と一致している
- [ ] 8月レポートで挙げたリスク3件が、9月レポートで引き継がれている
      （解決したものは「解消」と書かれている）
- [ ] アクションが表形式で、担当が姓のみ・期限が M/D 形式
- [ ] 末尾の注記文がある
- [ ] SKILL.md の `description` が、月次レポート以外の依頼で誤発火しない書き方になっている
- [ ] SKILL.md に「人に確認すること」が2件以上ある

## つまずきポイント

- **手順書をゼロから書こうとする**
  → 過去の完成品が3本もあるなら、そこから逆算するほうが速く、正確。
- **`description` が広すぎて誤発火する**
  → 「レポートを作る」だと単元07の分析レポートでも発火してしまう。
    「Altair CRM の月次経営レポート」のように固有名詞を入れる。
- **Skill が判断まで自動化してしまう**
  → 「リスクに何を挙げるか」は人が決める領域。「人に確認すること」を必ず書かせる。
- **Skill が長すぎて読まれない**
  → 100行以内。詳細は同じディレクトリの `reference.md` に逃がして参照させる。

## 発展課題

単元05（経費精算）や単元08（更新案内）も Skill 化する。
3つ揃うと、`.claude/skills/` が「この部署の業務手順書」になる。
チームで使うなら、リポジトリにコミットして共有する。
