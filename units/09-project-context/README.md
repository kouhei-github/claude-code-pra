# 単元09 CLAUDE.md で標準コンテキストを与える

|  |  |
|---|---|
| Cowork のユースケース | グローバル指示とプロジェクトで、毎回説明しなくて済む状態を作る |
| Claude Code での対応 | `CLAUDE.md` と `.claude/settings.json` に、社内の語彙・規約・禁止事項を書く |
| 所要時間 | 40分 |
| 使う機能 | `CLAUDE.md`（プロジェクト/ユーザー/ローカル）/ `/memory` / `.claude/settings.json` |

## 学習目標

1. 「毎回プロンプトに書いていること」を **常設のコンテキスト** に移す。
2. 3階層（ユーザー / プロジェクト / ローカル）の使い分けを理解する。
3. CLAUDE.md に書くべきこと・書くべきでないことの線引きができる。

## Cowork との対応

| Cowork | Claude Code | スコープ |
|---|---|---|
| グローバル指示 | `~/.claude/CLAUDE.md` | 自分の全プロジェクト |
| プロジェクト | `<repo>/CLAUDE.md`（コミットする） | チーム全員 |
| （相当なし） | `<repo>/CLAUDE.local.md`（gitignore） | 自分だけ・このリポジトリ |
| （相当なし） | `.claude/settings.json` | 権限・環境変数・フック |

## 素材

```
data/
  社内用語集と組織.xlsx
    ├ 社内用語集 … 15語（正しい表記 / 誤用されがちな表記 / 意味 / 使う場面）
    └ 組織と決裁 … 8組織（責任者 / 人数 / 決裁範囲 / 定例）
  文章スタイルガイド.md          敬体・数字・禁止表現・提案書の構成
  リポジトリの歩き方.md          どの依頼のときにどのファイルを見るか
  やり直しになった出力の実例.md   過去に差し戻された6例と、その理由
```

## 手順

### Step 1 — 何を常設化すべきか決める（10分）

単元01〜08 で自分が書いたプロンプトを見返し、**繰り返し書いていた制約**を洗い出す。
だいたい次のようなものが出てくるはずだ。

- `data/` は変更しない、`output/` にだけ書く
- 推測で埋めない。不明点は「要確認」として明示する
- 数字はソースを1つに限定する
- 削除ではなく退避

これらは毎回書くのではなく、CLAUDE.md に置く。

### Step 2 — CLAUDE.md を作らせる（15分）

### Step 3 — 効いているか試す（10分）

**素材を一切渡さずに**依頼を投げ、CLAUDE.md だけで正しい振る舞いをするか確認する。

### Step 4 — 削る（5分）

CLAUDE.md は長いほど良いわけではない。**守られなかった行は削るか、書き直す。**

## そのまま使えるプロンプト

**（A）CLAUDE.md の生成**

```
このリポジトリの CLAUDE.md を作ってください。

【材料】
- @units/09-project-context/data/社内用語集と組織.xlsx
- @units/09-project-context/data/文章スタイルガイド.md
- @units/09-project-context/data/リポジトリの歩き方.md
- @units/09-project-context/data/やり直しになった出力の実例.md

【出力】units/09-project-context/output/CLAUDE.md
  ## このリポジトリについて     … 3行以内
  ## 会社と製品の前提           … 社名・製品名の正式表記、組織と決裁範囲
  ## 用語                       … 表を使わず、間違えやすいものだけ箇条書きで
  ## 出力の規約                 … 敬体・数字・日付・禁止表現
  ## 作業のルール               … data/ と output/ の扱い、削除禁止、不明点の扱い
  ## よくある依頼と参照先       … 依頼の種類 → 先に読むファイル

【制約】
- 全体で120行以内。長い表を丸ごと転記しない
- 「やり直しになった出力の実例.md」の6例から導けるルールを、必ず全部含める
- 一般的なAIへの心構え（「丁寧に」「正確に」）は書かない。この会社固有のことだけ書く
- 各ルールは、守られたかどうかを後から判定できる書き方にする
```

**（B）効果測定**

```
（CLAUDE.md をリポジトリ直下に置いてから、/clear した上で）

@units/07-data-analysis-report/output/分析レポート.md をもとに、
ミナト製作所向けの案内文を1通書いてください。出力は units/09-project-context/output/テスト文.md。
```

このとき、**プロンプトに何も制約を書いていない**のに次が守られていれば CLAUDE.md が効いている。

- 「値上げ」ではなく「価格改定」になっている
- 「ご了承ください」を使っていない
- 製品名が `Altair CRM` になっている
- 金額が「1,234,567円（税抜）」形式
- 推測した箇所に「要確認」が付いている

**（C）設定ファイル**

```
.claude/settings.json を作ってください。

【出力】units/09-project-context/output/settings.json
- units/*/data/ 配下への Write / Edit を拒否する permissions.deny
- rm -rf を含む Bash を拒否する permissions.deny
- git status / git diff / python3 / ls / find を許可する permissions.allow

作ったら、各設定が何を防ぐのかを output/settings_説明.md に1行ずつ書いてください。
```

## 成果物

- `output/CLAUDE.md`（120行以内）
- `output/settings.json` と `output/settings_説明.md`
- `output/テスト文.md`（効果測定の結果）

## 合格チェック

- [ ] CLAUDE.md が120行以内
- [ ] 「やり直しになった出力の実例」6例すべてに対応するルールがある
- [ ] 各ルールが判定可能な書き方になっている（「丁寧に」等の心構えが無い）
- [ ] 制約を書かないプロンプトで、禁止語が使われなかった
- [ ] 製品名が `Altair CRM` に統一された
- [ ] settings.json で `units/*/data/` への書き込みが拒否される

## つまずきポイント

- **用語集を丸ごとコピーして数百行になる**
  → 長い CLAUDE.md は読まれ方が薄くなる。間違えやすいものだけ書き、
    全量は「必要なら `data/社内用語集と組織.xlsx` を読む」と参照先を書く。
- **「正確に」「丁寧に」といった心構えを書く**
  → 判定できないルールは効果がない。禁止語リストや形式の指定に置き換える。
- **効いているか確認しない**
  → 必ず `/clear` してから、制約なしのプロンプトで試す。
- **個人の好みをプロジェクトの CLAUDE.md に書く**
  → チーム共有のものと自分用（`CLAUDE.local.md` / `~/.claude/CLAUDE.md`）を分ける。

## 発展課題

`/memory` コマンドで CLAUDE.md を開き、単元10以降で気づいたルールを追記していく。
CLAUDE.md は書いて終わりではなく、**やり直しが出るたびに1行増える**運用物。
