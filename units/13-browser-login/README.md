|  |  |

## その前に：Claude Code のブラウザ連携は2ルートある

### ルートA — Claude in Chrome 拡張（公式・対話向き）

Claude Code は **Claude in Chrome 拡張** と連携できます。`claude --chrome` で起動すると、
ターミナルから実際の Chrome ウィンドウを操作できます。

```bash
claude --chrome          # このセッションだけ有効にする
/chrome                  # 接続状態の確認・再接続・既定で有効化
```

必要なもの（公式ドキュメント記載）:

- Chrome / Edge などの Chromium 系ブラウザ
- [Claude in Chrome 拡張](https://chromewebstore.google.com/detail/claude/fcoeoabgfenejglbffodgkkbkcdhcgfn) 1.0.36 以上
- Anthropic 直契約のプラン（Pro / Max / Team / Enterprise）
- `/login` でのサインイン（**API キーや長期トークンで認証している場合は使えません**）
- WSL では非対応

**このルートでの「自動ログイン」の正体は、ログインしないことです。**
拡張は **あなたのブラウザのログイン状態をそのまま共有**します。すでに Chrome で
サインイン済みのサイトなら、Claude はそのまま中に入れます。ID とパスワードを
打たせる必要がありません。

そして公式仕様として、**Claude はログイン画面や CAPTCHA に遭遇すると手を止め、
人間に操作を渡します**。これは機能不足ではなく設計です。認証は人がやる、
その後の面倒な作業を AI がやる、という線引きになっています。

### ルートB — Playwright MCP / Playwright スクリプト（非対話・定期実行向き）

夜間バッチや CI で人が見ていない状態で動かすなら、こちらです。

```bash
# MCP サーバーとして登録する（対話しながら操作したいとき）
claude mcp add playwright -- npx -y @playwright/mcp@latest

# スクリプトとして書く（定期実行したいとき）
pip install playwright && playwright install chromium
```

ここでの「自動ログイン」は次の2択になります。

| 方式 | 内容 | 向き |
|---|---|---|
| **セッション再利用** | 一度ログインして `storageState` に保存し、次回以降はそれを読む | 推奨。ログイン処理が1日1回で済む |
| **毎回入力** | ID とパスワードを毎回フォームに打つ | セッションが切れたときの復旧手段 |

**どちらの場合も、認証情報をスクリプトに直接書かないこと。** 環境変数か
シークレットマネージャから読みます。この単元でもそう書かせます。

### 使い分け

| | ルートA（Chrome 拡張） | ルートB（Playwright） |
|---|---|---|
| ログイン | 既存セッションを共有。ログイン画面では人に渡す | storageState 再利用 or フォーム入力 |
| 実行 | 目に見える Chrome ウィンドウ | ヘッドレス可 |
| 人の同席 | 必要 | 不要 |
| 定期実行 | 向かない | 向く |
| 向く仕事 | 調査、単発の入力代行、画面の確認、デバッグ | 毎日・毎週の定型作業 |

**この単元はルートA、単元14はルートB**を主に使います。
Chrome 拡張が使えない環境（API キー認証、WSL、法人プラン制約）の人は、
両方とも Playwright MCP で進めて構いません。

### 仕込んである罠（16個の一覧は `apps/rpa-lab/README.md`）

この単元で当たるのは主にこの4つです。

1. ログインしないと API が全て 401。データだけ取りに行っても1件も返らない
2. ログイン直後に1回だけ「お知らせ」モーダルが出る（2回目以降は出ない）
3. 一覧はロード中に**スケルトン行**を描く。`tr` を待つと空振りする
4. 検索は 350ms のデバウンス。入力直後に結果を読むと前の結果を読む

## 手順

### Step 1 — 接続する（10分）

```bash
cd apps/rpa-lab && npm run dev          # 別ターミナルで起動しておく
```

**ルートA の場合**


```bash
claude mcp add playwright -- npx -y @playwright/mcp@latest
```

### Step 2 — ログインしてみる（10分）

まずは素直に頼みます。ここで**ルートAは止まります**。それが正しい挙動です。

### Step 3 — 一覧を読ませる（15分）

ここで「待つ」の設計を学びます。1回目はたいてい 0 件と報告されます。
スケルトン行を掴んでいるからです。

### Step 4 — 手順書に落とす（10分）

うまくいった操作を、**次回そのまま再現できる手順書**にします。
これが単元14（自動化）の入力になります。

## そのまま使えるプロンプト

**（A）ログインと画面の把握**

```
http://localhost:4321 を開いてください。

【やること】
1. ログイン画面が出たら、私に知らせて止まってください（自分で認証情報を入力しない）
   ※ 私が手で入力します。すでにログイン済みなら、そのまま次へ進んでください
2. ログイン後に出るモーダルがあれば閉じてください
3. ダッシュボードに表示されている数値を読み上げてください
4. ナビゲーションにあるページを列挙してください

【制約】
- API（/api/...）を直接叩かないでください。画面を操作してください
- ページのソースを推測で語らず、実際に見えているものだけを報告してください
```

**（B）一覧の抽出**

```
受注一覧（/orders）から「申請中」の受注をすべて抽出してください。

【手順】
1. /orders を開く
2. ステータス絞り込みを「申請中」にする
3. 一覧の読み込みが終わるのを待つ
   ※ 読み込み中はスケルトン行が描かれます。データ行（tr[data-order-id]）が
     出るか、0件表示（[data-testid=no-results]）が出るまで待ってください
4. ページ送りをして最後のページまで辿る
   ※ 「次へ」を押したあと、ページ番号表示が変わるのを待ってから読んでください

【出力】units/13-browser-login/output/申請中一覧.csv
  受注番号,顧客名,担当者,金額,受注日,納期

【制約】
- API を直接叩かない。画面から読む
- 件数は画面の「N 件中〜」表示と一致すること。一致しなければ、
  どこでずれたかを報告してください
- 途中でセッションが切れたら（/?expired=1 に飛んだら）、私に知らせて止まる
```

**（C）セレクタの棚卸し**

```
/orders と /order-new の2画面について、自動化に使えるセレクタを調べてください。

【出力】units/13-browser-login/output/セレクタ設計.md
  画面 | 要素の役割 | セレクタ | 種別(data-testid / id / 構造) | 壊れやすさ(低/中/高) | 代替案

【調べること】
- data-testid が付いている要素と、付いていない要素
- 付いていない要素について、どういうセレクタなら壊れにくいか
- 「要素が存在する」だけでは不十分な要素（後から中身が入るもの）はどれか

【制約】
- 実際にページを見て書く。推測で書かない
- nth-child のような位置依存のセレクタを推奨する場合は、理由を書く
```

## 合格チェック

- [ ] ログイン画面で Claude が勝手に認証情報を入力していない（ルートA）
- [ ] 抽出した件数が、画面の「N 件中〜」表示と一致している
- [ ] 1ページ目だけでなく、最後のページまで辿れている
- [ ] `output/セレクタ設計.md` に、`data-testid` が無い要素の代替案が書かれている
- [ ] 「後から中身が入る要素」（顧客の `<select>` など）が特定されている
- [ ] API を直接叩いていない（`/api/` へのアクセスが手順に出てこない）

## つまずきポイント

- **一覧が「0件」と報告される**
  → スケルトン行を掴んでいます。`tr` ではなく `tr[data-order-id]` を待つ。
    「行がある」ではなく「データ行がある」を条件にします。
- **顧客の選択肢が見つからない**
  → `<select>` は空で描画され、あとから API 経由で選択肢が入ります。
    要素の存在ではなく、`option` が2つ以上になったことを待ちます。
- **検索結果が1つ前の状態**
  → デバウンス 350ms。入力直後ではなく、結果が変わったことを待ちます。
- **ルートAで「ログインして」と頼んだのに止まる**
  → 仕様どおりです。認証は人が通す。そこから先が自動化の範囲になります。
- **`claude --chrome` が使えない**
  → API キー認証では無効です。`/login` でサインインするか、ルートBに切り替えます。

## 安全に使うために

Chrome 拡張は**あなたのログイン状態をそのまま共有**します。銀行、社内の基幹システム、
本番管理画面にもアクセスできてしまうということです。

- 拡張のサイト権限設定で、**触ってよいサイトを明示的に絞る**
- 練習は専用のブラウザプロファイルでやる
- 「不可逆な操作」（送信・削除・購入・承認）は、対象と件数を必ず先に確認させる
- 録画（GIF）にはログイン中の画面が写る。共有前に中身を見る

単元03で「削除ではなく退避」を学びましたが、ブラウザではそれができません。
**押したら戻せない**のがブラウザ操作の一番の違いです。

## 発展課題

`/orders` の検索窓に自分の名前を入れて絞り込み、その結果だけを CSV にする、を
プロンプト1つでやってみる。次に `/clear` して同じプロンプトを投げ、同じ結果が
出るか確かめる。出なければ、手順のどこが暗黙になっているかが分かります。
