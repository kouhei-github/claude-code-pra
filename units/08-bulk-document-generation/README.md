# 単元08 定型文書の量産（30社分の更新案内を差し込みで作る）

|  |  |
|---|---|
| Cowork のユースケース | ひな形と一覧表から、宛先ごとの文書をまとめて生成する |
| Claude Code での対応 | 30社の契約更新案内をWordで生成し、条件分岐と送付管理表まで作る |
| 所要時間 | 45分 |
| 使う機能 | `docx` / `xlsx` スキル / 条件分岐の実装 / バッチ処理 |

## 学習目標

1. 単純な差し込みではなく、**顧客の状態で文面が変わる**分岐を実装させる。
2. 「送らない」という判断も出力に含めさせる（全件送るのが正解ではない）。
3. 30件を1件ずつ手で確認せずに済むよう、**検証可能な形**で管理表を出させる。

## 素材

```
data/
  契約更新一覧.xlsx
    ├ 契約更新一覧   … 30社 × 13項目（プラン/ライセンス数/年額/値上げ率/更新期限/
    │                   利用状況スコア/解約リスク/直近の課題/営業担当）
    └ 価格改定の背景 … 改定理由・据え置き対象・上限・問い合わせ窓口
  更新案内_テンプレート.md    差し込み変数付きのひな形
  文面ルール.md               分岐条件7つと禁止表現
  昨年の送付例_ミナト製作所.docx  文体の基準（実際に送ったもの）
```

### 実装すべき分岐（文面ルールより）

| 条件 | 挙動 |
|---|---|
| 値上げ率 > 0 | 価格改定の理由を1文添える |
| 値上げ率 > 5% | 末尾に「事前にお電話でご説明のお時間を〜」を追加 |
| 利用状況スコア < 60 | 金額の話より先に、定着支援の提案を1段落入れる |
| 解約リスク = 高 | **更新案内を送らない。**個別連絡の文面に差し替え、管理表に理由を記載 |
| プラン = エンタープライズ | 営業本部長 大河内 篤 との連名にする |
| 常時 | 禁止語（値上げ / ご了承ください）を使わない |

条件が重なる顧客がいる（例：スコアが低く、かつ値上げ率が高い）。優先順位を決める必要がある。

## 手順

### Step 1 — 分岐を表にして確認する（10分）

30通を作る前に、**どの顧客にどの分岐が当たるか**の表を出させる。
ここで条件の重複と優先順位を人間が決める。

### Step 2 — 1通だけ作って文体を合わせる（10分）

いきなり30通作らせない。1通作って `昨年の送付例` と読み比べる。

### Step 3 — 30通を生成する（15分）

### Step 4 — 管理表で検証する（10分）

## そのまま使えるプロンプト

**（A）分岐の割り当て表**

```
@units/08-bulk-document-generation/data/契約更新一覧.xlsx と
@units/08-bulk-document-generation/data/文面ルール.md を読んで、
30社それぞれにどの分岐が当たるかを表にしてください。文書はまだ作りません。

【出力】units/08-bulk-document-generation/output/分岐割当表.md
  会社名 | 値上げ率 | スコア | 解約リスク | プラン |
  適用する分岐（複数可）| 送付する/しない | 特記事項

  表のあとに「条件が2つ以上重なる顧客」の一覧と、
  その場合にどちらを優先すべきかの提案を書く

【制約】
- 分岐は文面ルール.md に書かれた6つのみ。勝手に増やさない
- 「送付しない」に該当する顧客は理由を明記する
- 判断がルールから一意に決まらない組み合わせは、提案として書き、断定しない
```

**（B）1通だけ試作**

```
@units/08-bulk-document-generation/output/分岐割当表.md で
「値上げ率5%超」かつ「スコア60以上」に該当する顧客を1社選び、更新案内を1通だけ作ってください。

【出力】units/08-bulk-document-generation/output/letters/_試作.docx
【文体の基準】@units/08-bulk-document-generation/data/昨年の送付例_ミナト製作所.docx
【ひな形】@units/08-bulk-document-generation/data/更新案内_テンプレート.md

【制約】
- 禁止語（値上げ / ご了承ください）を使わない
- 「〜させていただきます」は1通に1回まで
- 金額は「1,234,567円（税抜）」形式
- 昨年の送付例と段落構成・敬語のレベルを揃える
```

**（C）30通の一括生成**

```
試作の文体で、30社分の更新案内を生成してください。

【出力1】units/08-bulk-document-generation/output/letters/<更新期限YYYYMMDD>_<会社名>_更新案内.docx
  解約リスク=高 の顧客は、更新案内ではなく個別連絡の文面（値上げに触れない）にする

【出力2】units/08-bulk-document-generation/output/送付管理表.xlsx
  会社名 | 先方担当者 | 更新期限 | 現行年額 | 更新後年額 | 値上げ率 |
  適用した分岐 | 送付要否 | 送付しない理由 | ファイル名 | 連名の有無

【制約】
- 1社1ファイル。ファイル名に会社名の正式名称を使う
- 禁止語チェックを生成後に自分で実行し、違反があれば直してから完了報告する
- 生成した通数と、送付管理表の行数が一致することを確認する
- 契約更新一覧.xlsx は変更しない
```

**（D）検証**

```
units/08-bulk-document-generation/output/ の検証スクリプトを書いて実行してください。
出力: units/08-bulk-document-generation/output/verify_letters.py

検証項目:
1. docx の件数 == 契約更新一覧の30社 - 解約リスク高の社数 + 個別連絡文の社数（= 30）
2. 全docxに禁止語（「値上げ」「ご了承ください」）が含まれない
3. 値上げ率>5% の社のdocxに「事前にお電話で」が含まれる
4. スコア<60 の社のdocxで、定着支援の段落が金額の段落より前にある
5. エンタープライズ契約のdocxに「大河内 篤」が含まれる
6. 解約リスク高の社のdocxに金額の記載がない
7. 送付管理表の行数 == 30

項目ごとに PASS/FAIL と、FAIL の場合は該当会社名を出力する。
```

## 成果物

- `output/分岐割当表.md`
- `output/letters/*.docx`（30通）
- `output/送付管理表.xlsx`
- `output/verify_letters.py` と実行結果

## 合格チェック

- [ ] 検証スクリプトが7項目すべて PASS
- [ ] 解約リスク「高」の顧客に、値上げの記載がない
- [ ] スコア60未満の顧客で、定着支援の話が金額より先に来ている
- [ ] エンタープライズ3社が連名になっている
- [ ] 送付管理表を見れば、誰に何を送ったか / 送らなかった理由が分かる
- [ ] `契約更新一覧.xlsx` が変更されていない

## つまずきポイント

- **全30社に同じ文面を送ってしまう**
  → 分岐割当表を先に作らせるのが効く。表がなければ分岐は実装されない。
- **「送らない」判断が出力から消える**
  → 管理表に「送付しない理由」列を必ず作らせる。空欄の行があれば見落としが分かる。
- **禁止語チェックを人間がやる羽目になる**
  → 検証スクリプトを書かせる。30通を目視するのは現実的でない。
- **条件が重なった顧客の優先順位を勝手に決める**
  → 分岐割当表の段階で「提案として書き、断定しない」と指示する。
