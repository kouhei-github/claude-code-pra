# 単元03 ファイル整理と一括リネーム

|  |  |
|---|---|
| Cowork のユースケース | 散らかったフォルダを指定して、階層設計・自動仕分け・一括リネームをさせる |
| Claude Code での対応 | 42ファイルの「受信箱」を命名規則に沿って整理し、重複を安全に退避する |
| 所要時間 | 35分 |
| 使う機能 | Bash ツール / Plan mode / 実行前の dry-run |

## この単元でやること

命名も置き場所もバラバラな42ファイルの「受信箱」を、命名規則に沿って整理させます。
ポイントは**いきなり実行させないこと**。まず Plan mode で移動計画の表だけを出させ、
顧客名がファイル名ではなく中身から判定されているか、重複判定が内容比較で行われているかを
人間がレビューしてから実行に移します。削除は禁止で、不要なものは退避します。

| | |
|---|---|
| 入力 | 受信箱/（42ファイル。md・csv・xlsx が混在）＋ 命名規則.md |
| 出力 | `output/整理計画.md`（3つの表）＋ `output/整理ログ.md` ＋ 整理後の `data/受信箱/` |
| 中心にある判断 | 「中身を読んでから分類する」を守らせること。名前だけで推測させない |

## 成功の定義

> **`rm` を1度も使わずにファイル総数が減っておらず、判定できなかったファイルが `_要確認/` に分けられていること。**

次が満たせていれば合格です。細かい確認項目は末尾の「合格チェック」にあります。

- `無題ドキュメント.md` `先方から届いたやつ.md` が中身から顧客判定されているか `_要確認/` にある
- `リード一覧.csv` と `リード一覧 のコピー.csv` が**内容一致**として検出されている
- `rm` が1回も実行されていない（`find data -type f | wc -l` が減っていない）
- `sakura-foods` `sakurafoods` `サクラフーズ` が同じフォルダに入っている

## 学習目標

1. **中身を読んでから**分類させる（ファイル名だけで判断させない）。
2. 破壊的な操作（削除・上書き）を禁止し、可逆な操作（移動・コピー）に置き換える。
3. dry-run（計画表を先に出させる）→ 承認 → 実行、という安全な進め方を身につける。

## 素材

```
data/
  命名規則.md          営業部のフォルダ構成とファイル名ルール
  受信箱/              42ファイル。命名も置き場所もバラバラ
    見積書_ミナト製作所_最新.md
    見積書_ミナト製作所_最新(2).md
    提案書ドラフト_v2_修正版_最終_FIX.md
    リード一覧 のコピー.csv
    あとで整理/        サブフォルダにも紛れている
    ...
```

わざと入れてある罠：

- 「最新」「最終」「FIX」「修正版」が積み重なった版数不明のファイル
- 内容が完全に同じ重複ファイル（`リード一覧.csv` と `リード一覧 のコピー.csv`）
- ファイル名から顧客が分からないもの（`無題ドキュメント.md`、`先方から届いたやつ.md`）
- 表記ゆれ（`sakura-foods` / `sakurafoods` / `サクラフーズ`）
- 日付がファイル名に無く、**中身にしか書いていない**もの

## 手順

### Step 1 — 規則を読ませて、計画表を出させる（15分）

Plan mode（`Shift+Tab`）で、下の「そのまま使えるプロンプト（A）」を投げる。
**この段階では1ファイルも動かさせない。** 出てくるのは移動計画の表だけ。

### Step 2 — 計画表をレビューする（10分）

ここが本番。次を目視で確認する。

- 顧客名が中身から判定されているか（ファイル名だけで推測していないか）
- 日付が中身の「作成日」から取られているか
- 重複判定が「名前が似ている」ではなく **内容の一致** で行われているか
- 判定できなかったファイルが `_要確認/` に分けられているか（無理に分類させない）

### Step 3 — 実行させる（10分）

計画表を承認したら「(B)」を投げて実行させる。実行後は `git status` で確認。

2. 内容から「顧客名」「日付」「種別」を判定する。ファイル名だけで推測しない
3. 内容が同一のファイル組をハッシュまたは内容比較で特定する

【出力】units/03-file-organization/output/整理計画.md に、次の3つの表を作る

【制約】
- 削除は一切しない。重複は _アーカイブ/ への移動として計画する
- 判定できないファイルは無理に分類せず、必ず表3に入れる
- 日付は中身に書かれているものを優先する。無い場合のみファイル名から取る

## 合格チェック

- [ ] `無題ドキュメント.md` `先方から届いたやつ.md` が中身から顧客判定されている、または `_要確認/` にある
- [ ] `リード一覧.csv` と `リード一覧 のコピー.csv` が内容一致として検出されている
- [ ] 「提案書ドラフト_v2_修正版_最終_FIX.md」系4ファイルの版数が整理されている
- [ ] `sakura-foods` `sakurafoods` `サクラフーズ` が同じフォルダに入っている
- [ ] `rm` が1回も実行されていない
- [ ] ファイル総数が減っていない（`find data -type f | wc -l` で確認）

## つまずきポイント

- **いきなり実行させると戻せない**
  → Plan mode と「計画表だけ」の指示を必ずセットで使う。
- **`(2)` や「のコピー」を機械的に重複と決めつける**
  → 中身が違うのに消される事故が起きる。内容比較を明示的に指示する。
- **`あとで整理/` サブフォルダを見落とす**
  → 「サブフォルダ含む」と書く。

## 発展課題

整理を毎週回せるように、判断ルールを `.claude/skills/` の Skill に切り出す（単元10）。
さらに、`_要確認/` に残ったファイルだけを人間がさばく運用に落とすと、
毎週の作業時間が「全部を仕分ける」から「例外だけ見る」に変わる。
