# Altair 受注管理（RPA 練習用ダミーシステム）

単元13・14 で Claude Code に操作させるための、**わざと自動化しにくく作った**業務システムです。
架空の SaaS 企業「株式会社アルタイル」の社内システムという設定で、実在の企業・個人とは関係ありません。

依存パッケージはゼロ。Node 20 以上があれば動きます。

## 起動

```bash
cd apps/rpa-lab
npm run dev          # → http://localhost:4321
```

### 練習用アカウント

| 役割 | メールアドレス | できること |
|---|---|---|
| 営業 | `tanaka@altair.example.co.jp` | 受注の登録・申請 |
| 承認者 | `okochi@altair.example.co.jp` | 上記に加えて承認・差戻し |

パスワードの既定値は両アカウントとも `demo` です。環境変数で変更できます。

```bash
RPA_SALES_PASSWORD=... RPA_APPROVER_PASSWORD=... npm run dev
```

**パスワードをソースに書いていないのは意図的です。** 弱い既定値にしてあるのも同じ理由で、
強そうな文字列を書くと「守るべき秘密」に見えてしまうためです。
単元14 では RPA 側にも同じ規律（認証情報は環境変数から読む）を要求します。

## 画面

| パス | 内容 |
|---|---|
| `/` | ログイン |
| `/dashboard` | 件数・金額・承認待ちの集計 |
| `/orders` | 受注一覧（検索・絞り込み・ページ送り・詳細モーダル） |
| `/order-new` | 受注登録（4ステップのウィザード） |
| `/approvals` | 承認待ち一覧（承認 / 差戻し。差戻しは理由必須） |
| `/reports` | 月次レポート生成（非同期ジョブ → CSV ダウンロード） |

## わざと入れてある「自動化しにくさ」

RPA の練習台なので、現場のシステムでよく困る要素を意図的に仕込んであります。

| # | 仕掛け | RPA 側に要求されること |
|---|---|---|
| 1 | ログインしないと API が全て 401 | 認証を通すこと。データだけ取りに行っても何も返らない |
| 2 | ログイン直後に1回だけお知らせモーダルが出る | 出るかもしれないものを閉じる（出ない場合もある） |
| 3 | 一覧はロード中にスケルトン行を描く | `tr` を待つと空振りする。データ行か0件表示を待つ |
| 4 | `<select>` は空で描画され、後から選択肢が入る | 「要素がある」ではなく「選択肢が入った」を待つ |
| 5 | 一覧は 20 件ずつのページ送り | ページを辿る。ページ番号の変化を待つ |
| 6 | 検索は 350ms のデバウンス | 入力直後に結果を読まない |
| 7 | API に 200〜1100ms の遅延 | `sleep` ではなく条件待ちにする |
| 8 | 4ステップのウィザード、各ステップでバリデーション | 進めなかったことを検知し、画面のエラー文を拾う |
| 9 | 明細追加はモーダル内のオートコンプリート | 候補が出るのを待ってから選ぶ |
| 10 | 差戻しは理由 10 文字以上が必須 | 画面のバリデーションに合わせる |
| 11 | 送信ボタンは処理中 `disabled` になる | 二重クリックしない。完了条件で待つ |
| 12 | トーストは 5 秒残り、積み重なる | 「最初のトースト」を掴むと前の操作の結果を読む |
| 13 | レポートは 3.5 秒の非同期ジョブ | ポーリングして完了を待つ |
| 14 | セッションは 30 分で失効し `/?expired=1` へ飛ぶ | 失効を検知して入り直す |
| 15 | ログイン 5 回失敗で 60 秒ロック | 総当たりを試みると止まる |
| 16 | `data-testid` は主要な要素にだけ付けてある | 無いところは自分でセレクタを設計する |

## データ

- 受注 120 件・顧客 30 社・商品 8 点を、固定シードで決定論的に生成しています。
- 登録・承認の結果はサーバのプロセス内メモリに持ちます。
- 初期状態に戻す: `DELETE /api/meta?reset=1`（要ログイン）。サーバの再起動でも戻ります。

## Vercel へのデプロイ

ビルド不要の静的ファイル＋サーバーレス関数（4本）です。

```bash
cd apps/rpa-lab
npx vercel            # 初回。プロジェクトを作成
npx vercel --prod     # 本番デプロイ
```

- Framework Preset は **Other**、Build Command は空のままで構いません。
- 環境変数を設定してください。
  - `RPA_LAB_SECRET` — セッションの署名鍵。未設定の場合は起動のたびにランダム生成され、
    再起動でログイン状態が切れます
  - `RPA_SALES_PASSWORD` / `RPA_APPROVER_PASSWORD` — 練習用アカウントのパスワード
    （未設定なら `demo`）。公開URLに置く場合は必ず設定してください
- サーバーレス環境ではインスタンスが入れ替わると登録データが初期状態に戻ります。
  演習をじっくりやるときは `npm run dev` のローカル実行を勧めます。
  Vercel は「ネットワーク越しの本物っぽい相手」を用意したいときに使ってください。
- `X-Robots-Tag: noindex, nofollow` を付けてあります。

## API

| メソッド・パス | 用途 |
|---|---|
| `POST /api/auth` | ログイン（httpOnly クッキーを発行） |
| `GET /api/auth` | 現在のセッション |
| `DELETE /api/auth` | ログアウト |
| `GET /api/meta` | 商品・顧客・集計 |
| `DELETE /api/meta?reset=1` | 練習データを初期化 |
| `GET /api/orders` | 一覧（`q` `status` `page` `perPage` `sort`）/ `?id=` で1件 |
| `POST /api/orders` | 受注を作成して申請中にする |
| `PATCH /api/orders` | 承認 / 差戻し（承認者のみ） |
| `POST /api/reports` | レポート生成ジョブを開始 |
| `GET /api/reports?job=` | 進捗 / `&download=1` で CSV |

API が使えることは知っておいて構いません。ただし単元13・14 の演習は
**画面を操作すること**が目的なので、API を直接叩いて済ませると練習になりません。
API は答え合わせと事後検証に使ってください。

## これは本番用の実装ではありません

セッションは HMAC 署名したクッキーですが、パスワードの比較は平文で行っており
（ハッシュ化していません）、データもプロセス内メモリです。
学習者に「ログインを通らないと1件も見えない」状態を作ることだけが目的の実装です。
